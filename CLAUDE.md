# CLAUDE.md — контекст проекта Steam Wishlist Sorter

Этот файл читается в начале каждой сессии. Правила отсюда действуют всегда,
даже если в промпте сессии они не повторены.

## О проекте

Steam Wishlist Sorter — локальное веб-приложение для ранжирования списка желаемого
в Steam. Пользователь импортирует свой wishlist, раскладывает позиции по категориям,
затем упорядочивает их внутри категорий попарными сравнениями и получает итоговый
пронумерованный список с экспортом в JSON, CSV и текст.

Цель — инструмент, которым реально пользуются с wishlist на 200+ позиций, а не
демонстрация алгоритма. Проект публичный, идёт в портфолио: код, комментарии,
история коммитов и README читают посторонние люди.

## Стек

- Vanilla JS, ES-модули. Без фреймворков, без сборщика, без транспиляции.
- HTML + CSS без препроцессоров. Тёмная тема, родственная Steam, но не копия.
- Node нужен только для тестов и для локального статического сервера (`server.js`,
  чистый Node без зависимостей). ES-модули не работают через `file://`, поэтому
  приложение открывается с локального HTTP-сервера.
- Минимальная версия Node — 20. Разработка ведётся на 24 LTS. В CI указывается та же
  мажорная версия, чтобы локальный прогон и GitHub Actions не расходились.
- Линтеров, форматтеров и CI-инструментов сверх GitHub Actions не добавляем.

## Тесты

- Только встроенные `node:test` и `node:assert`. Ничего больше.
- **Сторонних зависимостей у проекта нет и не должно появиться.** `node_modules`
  не создаётся, `npm install` не запускается, `npx <пакет>` не предлагается —
  это тянет пакеты из сети и противоречит духу локального приватного приложения.
- `package.json` существует по сути ради одного скрипта: `"test": "node --test"`.
- Запуск: `node --test`.

## Структура

```
index.html                 точка входа приложения
styles.css                 стили
server.js                  локальный статический сервер на чистом Node
start.bat                  запуск сервера (Node, с запасным вариантом на Python)
package.json               только "test": "node --test"
src/                       исходный код
  model.js                 модель позиции, категории, нормализация
  import.js                импорт произвольного JSON и приведение к модели, отчёт импорта
  storage.js               обёртка над localStorage: сохранение, экспорт и импорт состояния
  ranking.js               ядро ранжирования: граф предпочтений, планировщик пар, результат
  ui-*.js                  экраны интерфейса поверх ядра, без дублирования логики
tests/                     тесты на node:test
  fixtures/                тестовые и демонстрационные наборы данных
userscripts/               Tampermonkey-скрипты для страницы Steam Wishlist
docs/                      документация
  screenshots/             скриншоты для README
.github/workflows/         CI: прогон тестов на push и pull request
```

Пустые папки удерживаются в git файлами `.gitkeep`. Как только в папке появляется первый
настоящий файл, `.gitkeep` из неё удаляется — он больше ничего не держит.

Модель позиции: `{ appId, title, url, imageUrl, wishlistPosition, kind: 'game' | 'dlc' | 'unknown' }`.
Идентификатор — `appId`.

Вся логика ранжирования живёт в `ranking.js`. UI её не дублирует и не пересчитывает.
`storage.js` не зависит от DOM — в тестах подменяется заглушкой.

## Version control

- Основная ветка — `master`. Все Pull Request идут в `master`.
- **Claude Code никогда не выполняет изменяющих git-команд.** Ни `git commit`, ни `git add`,
  ни `git push`, ни `git branch`, ни `git checkout`, ни `git merge`, ни `git reset`,
  ни `git stash`, ни любых других, меняющих историю, ветки или индекс.
- Версионированием управляет пользователь вручную в графическом клиенте Fork.
  Ветку под сессию он создаёт сам до её начала.
- В конце каждой сессии Claude выводит текстом предлагаемые сообщения коммитов
  с указанием, какие файлы входят в каждый коммит, но не применяет их.
- Читающие git-команды (`git status`, `git diff`, `git log`, `git show`) **разрешены
  и приветствуются**: они ничего не меняют. Перед тем как предложить разбивку на коммиты,
  сверься с `git status` и `git diff --stat`, а не полагайся на память о том, что делал
  за сессию: иначе в списке файлов появятся пропуски и лишние строки.

## Приватность

Пользовательские данные никогда не покидают браузер и никуда не отправляются.
Единственный внешний запрос за всё время работы приложения — загрузка обложек игр
с CDN Steam по публичному URL; этот запрос отключается тумблером в настройках.

Формулировки вида «никаких внешних запросов» без этой оговорки неверны и не должны
появляться ни в README, ни в интерфейсе, ни в комментариях. Точная формулировка выше —
единственная допустимая.

## Результат доступен в любой момент

Сортировка длинная: 200 позиций — это порядка тысячи сравнений, и реальный пользователь
бросит её на середине. Поэтому незавершённое состояние обязано давать осмысленный
итоговый список: всё, что уже выводится из графа предпочтений, упорядочивается
топологически, а позиции с ещё не определённым порядком получают стабильный запасной
порядок по `wishlistPosition`. Итоговый экран честно показывает, какая часть списка
упорядочена сравнениями, а какая стоит в запасном порядке.

`getResult()` обязан работать на любом состоянии, включая пустое и незавершённое.
Инструмент, который до самого конца не отдаёт ничего, бесполезен.

## Примечание про фикстуры

`tests/fixtures/` коммитится в репозиторий и не подпадает под `.gitignore`.
Это не временные файлы: демонстрационный набор оттуда используется и тестами,
и кнопкой «Загрузить демо-набор» в интерфейсе.
